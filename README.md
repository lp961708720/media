## 0.4.11：独立 AI 对话与每次实时检索

侧栏新增「AI 对话」。选择本轮模型及 Skill，可使用写作、编辑、去 AI 味、审阅、研究、拆解等各用途的文字规则与参考文件。聊天按创作空间保存，支持多轮追问、逐轮切换模型和 Skill。现有稿件不会被聊天覆盖；完整回答可显式另存为新稿件。仅列出当前空间可用的规则，保留账号范围与版本限制。

「按 Skill 执行」按所选规则完成任务；「发送对话 / 仅提问」用于解释和讨论。指定的 wechat-write 执行写作时，软件先真实调用已适配的红狐接口，再将当次结果交给模型。每次重新检索，不复用或跳过；其他 Skill 不自动触发红狐查询。仅提问也不查询。查询前确认关键词、时间范围和积分使用；失败或无匹配文章时停止，不自动充值或付款。

Skill 中写有接口地址，不代表模型已经拥有工具。除指定红狐适配器外，通用脚本、浏览器与其他外部接口没有自动执行能力；其他 Skill 仍可使用其文字方法参与对话。

文章顶部的快捷 / 研究写作决定资料范围，不决定红狐查询。快捷写作使用关联灵感和已选素材；研究写作额外带入项目研究和已确认卡片。引用完整拆解会传入原文、确认的完整报告、证据及未知项作为写作参考，不保证每一项分析都自动转成文章段落。

## 0.4.10：逐段审阅与公众号排版

在文章工作台点击「检查修改 → AI 审阅当前正文」，可查看总体判断、原文段落、具体问题与替换建议，先比较再逐条采纳。涉及事实、数据或版权的建议需人工核实；AI 没有联网核查工具，不能把审阅当作事实核查证明。人工改稿后旧建议失效，重新审阅可生成新报告。

公众号稿件默认进入连续长文排版。软件本地识别推荐标题和正文，提供清爽阅读、温柔叙事、专业深度、杂志风四种模板。标题摘要分别复制，正文使用「复制公众号富文本」粘贴到公众号编辑区，也可导出 HTML 与原图。公众号后台可能过滤内嵌图片，需要重新上传原图并检查粘贴效果。设置独立保存，不改原稿；需要时可通过修改对比同步排版文字到稿件。图片卡片模式仍可切换使用。

桌面富文本复制通过只写剪贴板桥接实现：仅接受当前应用主窗口、同一本地来源的请求，没有剪贴板读取接口。费用预算、文章对话与红狐写作流程沿用。

## 0.4.9：文章对话与 Skill 检索流程

「文章对话」按稿件保留多轮提问与回答，可选择参考哪次生成的来源与 Skill。讨论只生成回答，不能作为正文直接采纳；确需改稿时点「将本轮要求用于改写」，改写结果仍先比较再采纳。历史问题和回答保存在 SQLite 与备份中，费用继续检查原有预算。

公众号文案创作 Skill 中声明的红狐爆款检索现在有写作前置入口：查看关键词、时间和积分提示后查询一次，结果保存并引用，再执行写作；已有快照可复用，不重复消耗查询积分。个人风格参考可在同一面板补充。缺少 Key、积分不足、接口错误或空结果时明确提示，不假装已查询；可以明确选择仅用现有资料。检索通过应用适配的官方接口，不运行 Skill 附带脚本或充值流程。


## 0.4.8：围绕同一篇文章完成创作

- 侧栏收为工作台首页、灵感与研究、文章工作台、内容库、发布与复盘、设置。原有账号、模型、Skill、工作流、评论和数据入口仍可在分区中访问。
- 文章保留同一编辑器，资料与读者、写作、检查修改、去 AI 味、排版导出、发布复盘按需切换；首页可以返回上次文章，旧项目链接自动打开绑定文章。
- 快捷写作不强制填写两张卡。研究写作将当前项目选定的完整来源、已确认且未过期的人群卡和写作卡带入普通正文生成，资料清单与调用使用同一份研究描述。未确认、已变化和暂未引用的材料明确列出。
- 研究变化会阻止直接采纳旧结果；历史输入快照仍保留。人工正文修改可以比较后采纳，过期来源在调用前提示处理。
- 当前文章可记录人工检查版本、切换去 AI 味规则、比较采纳、编辑图文并导出、创建本篇排期、回填发布版本和录入本篇数据。正文变化会更新检查状态，正文与排版保存按顺序提交。
- Skill 管理明确显示文字规则、只读脚本与 Redfox 配置范围。本版没有增加脚本执行器。


## 0.4.6：自动输出额度与截断恢复

官方 DeepSeek 混合模型的旧配置升级后默认按单次费用预算与供应商输出能力自动分配额度，忽略旧的默认 8000；手动模式与本次手动覆盖仍按明确设置执行。其他服务可读取模型目录中的最大输出能力，或在配置中填写后启用自动模式。没有能力信息时不会猜测一个更大的固定上限。

自动额度仍受模型本身能力和你保留的费用预算约束；不代表无限输出，也不保证供应商必定生成到该长度。DeepSeek 官方资料说明，不传 max_tokens 仍会采用其默认值，因此本版采用明确计算的额度。自动模式下不显示只供手动模式使用的默认 Token 输入。

输出截断与完整任务失败分开呈现：保留所有已返回文本，可查看、复制、免费另存为可编辑的未完成草稿，或按自动额度接续。接续是一次新的预算受控调用，合并原有部分文本形成新候选，旧记录保留，不自动循环扣费。正文写作页不再显示“重新拆解”等结构化任务专用提示。输入、输出、已报告的推理 Token 分开显示。

## 0.4.5：创作恢复、后续 Skill 与完整研究链路

- 按账号记住当前稿件，生成记录按稿件查询；空白且未变更的稿件会载入已完整生成的初稿，离开页面后仍可从数据库恢复。已有正文保持人工比较与采纳。
- 正文、生成文章均可交给所选写作、编辑或去 AI 味 Skill 继续处理；无需先采纳，支持连续处理，每次保留输入和规则版本快照。
- 编辑器上方提供生成记录、修改对比、版本历史及引用资料。手工编辑与 AI 修改均可比较，按文字高亮增删；长文比较保留全文。原稿变化时须重新核对当前版本，仍使用并发版本检查。
- 修复版本历史函数遮蔽浏览器 history 导致创作项目无法打开；修复同页面不同稿件的导航与返回。
- 拆解结果增加按所选 Skill 原框架保留的完整报告和补充字段，确认时保留原始模型输出。灵感卡摘要仍是预览，可查看完整拆解；开始创作引用整份已确认分析、受众与原文，来源过期时阻止引用旧结论。旧记录缺少的完整报告不能凭空补齐，需重新拆解。
- 模型配置增加 Redfox 专用 Key 加密配置；AI 创作提供显式热点素材查询。一次查询只请求一次官方接口，结果保存为本账号素材并可引用。Key 不进入模型输入、备份、源码或安装包；未提供外部数据时按已有资料写作，不把工具能力说明当成文章。
- Redfox 查询可能消耗其服务积分，与模型预算分开；须在应用界面确认后发起，不自动扩展查询、不执行 Python、不充值或付款。接口返回标题、摘要和互动快照，不能当作已读完整原文。

## 0.4.4：写作方式下拉框与平台不匹配处理

AI 创作的写作方式改为下拉框，选择后自动保存到本稿，显示当前使用的规则与版本。可直接切回 AI 直接写作；旧规则失效时明确显示不可用，不伪装成直接写作。

新增「稿件目标平台」，只影响这篇稿件。选到平台不一致的写作 Skill 时，可选择仅切换本稿目标平台，或者保留稿件平台并将该 Skill 设为通用。后者会影响这份 Skill 在其他稿件中的可用范围，须在界面明确选择后保存。切换稿件平台时，不匹配的写作或已启用的后处理规则会取消选用；编辑中的正文同时保存。账号可用范围、停用状态、费用预算仍按原规则检查。

## 0.4：原文驱动的 AI 对标文章拆解

「对标研究 → AI 拆解文章」只需提供标题、原文链接与正文，选择模型及文章拆解 / 对标研究 Skill。可直接保存原文，稍后继续；未分组文章自动归档，不需要先填写人工分析。

AI 按选题立意、标题封面、结构框架、素材论据、文风表达、转化互动六大维度，逐项给出分析、原文引句与借鉴边界，另按身份线索、知识水平、需求、场景、情绪、阅读动机、行动意图和非目标边界拆解受众。结果区分直接观察、推断和未知；引用必须能在所提供材料中逐字找到。

报告独立保存，人工核对并确认后才作为后续选题和创作项目的参考。已确认受众与拆解会传入人群卡 / 写作卡生成上下文；原文修改后会标记过期并阻止继续引用旧结论。保留原文、模型、Skill 版本、输入与运行记录，可取消、导出 Markdown；旧版人工笔记保留。

原文链接仅作来源记录，不自动抓取。可补充封面、排版和评论文字描述；未提供时明确未知，没有发送图片像素给模型。打开率、完读率和转化率没有实测记录时不作效果结论。详细报告建议模型最大输出配置为 8000 Token 或以上；仍遵守所配置上限和预算，失败不自动追加收费调用。

## 0.3.1：常见 Skill 原包导入

可直接导入常见 SkillHub / 文本 Skill ZIP，无需手动修改原包：识别 `_meta.json` 等包元数据，忽略 macOS 附带文件，支持外层目录、辅助列表 / 嵌套声明和多行描述。缺少 `display_name` 时使用标题或 name；缺少 `version` 时读取包版本或设置工作台初始版本，并在预览中明确提示。

导入前先展示名称、版本、参考文档与兼容处理说明。原始 SKILL.md 留存为来源快照，规则正文与参考文档保留，规范化元数据用于工作台版本管理。工具声明不会授予本机能力；含程序、越界路径、符号链接或损坏内容的包会指出具体文件和原因。当前仍以文本规则为执行范围，不声称支持全部 YAML 语法或可执行 Skill。

## 第一次使用

1. 建立自己的公众号或小红书账号，填写定位与创作规则。
2. 在模型配置中填接口协议、Base URL、模型 ID 和真实价格；需要时录入自己的 API Key。
3. 新建稿件，默认直接写作；如需 Skill 或后处理，明确选择。
4. 从本机上传图片或导入文稿，编辑正文，生成和比较独立 AI 候选。
5. 排版中心编辑卡片、核对溢出与平台规则，然后导出。
6. 如需发内容，到平台手工发布，再回填真实链接与时间。仅排期/导出不算发布成功。
7. 导入真实指标，生成复盘或记录真实评论。

公网 AI 接口会把你选定的当前账号资料发给所配置的服务商。本机模型显式授权后只访问回环接口。模型名称、参数能力、价格和平台规则由你配置，不写死某个“最新型号”。

图像模型在协议中选择「图像生成 / Images API」，填写每张估算价格，然后从素材库生成。只接受 Base64 图片结果，不自动下载第三方返回的图片 URL。

## 数据、凭证和备份

- 数据目录可从 Mac 应用菜单「打开数据目录」访问。通常为 macOS 的 `~/Library/Application Support/Media Studio`，Windows 的 `%APPDATA%/Media Studio`。
- API Key 在本机服务端 AES-GCM 加密；主密钥由 Electron 系统安全存储保护，前端只看掩码。
- 系统凭证库连接在界面打开后进行。暂不可用时，仍能编辑本机内容；新 Key 保存受阻。可从应用菜单重新连接。
- 可选解锁密码只保存 scrypt 加盐摘要，用于本机应用访问门禁；它不是整个 SQLite 文件的磁盘加密。
- JSON / gzip 备份包含账号、图片及历史快照、修订、复盘、评论、工作流、导入批次和运行记录，不含 API Key 或解锁密码。
- 备份恢复只支持空工作空间，校验图片哈希后事务导入；恢复后重新录入 Key。
- 每日备份和排期在应用运行时执行。工作流新步骤在锁定时停止推进；关闭应用不会在系统后台继续执行。
- 指标空值是未知，0 是确认的零；累计数据按每篇作品最新快照统计。费用按填写单价估算，不能替代服务商账单。
- 数据备份不自动跨电脑同步。可把导出的备份带到另一台电脑导入。

## 源码运行与验证

需要 Node.js 24 或更新版本。核心服务和测试无第三方运行时依赖。

```sh
npm run check
npm test
npm run dev
```

打开终端显示的本机地址（默认 `http://127.0.0.1:4327`）。开发数据单独存放在 `.local/`，不与桌面正式数据混合。

开发桌面窗口和生成常规安装包需要先安装开发依赖：

```sh
npm ci
npm run desktop
npm run dist:mac
npm run dist:win
```

可用 `scripts/package-portable.mjs` 从已下载的官方 Electron ZIP 制作便携客户端；该脚本会核验 Electron 包自带的 SHA-256 清单。Windows 原生运行需在 Windows 电脑验收。

```sh
node scripts/package-portable.mjs darwin arm64 /path/to/runtime.zip /path/to/checksums.json /path/to/output
```

`npm run build` 生成 UI 与模块构建产物，不会部署网站。GitHub 工作流保留手动构建能力，不自动创建 Release。

## 工程结构

- `desktop/`：Electron、系统凭证库、窗口和下载。
- `scripts/`：本机服务、SQLite 迁移、网络边界、本机解锁/备份/排期、构建与打包。
- `worker/`：账号与内容 API、AI 网关、运行治理、图像生成、Office 解析及扩展模块。
- `public/`：原工作台 UI 和 0.2 个人功能扩展。
- `drizzle/`：按顺序执行的增量 SQL 迁移。
- `tests/`：41 项核心与个人功能测试，包括中断、隔离、预算、迁移和备份哈希。

接口实现参考 [OpenAI Responses 流式文档](https://developers.openai.com/api/docs/guides/streaming-responses)、[Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)、[Gemini generateContent](https://ai.google.dev/api/generate-content)。模型端真实联调需使用你自己的授权与额度；测试采用受控响应，不冒充付费调用成功。

## 0.4.1 输出限制修复

已有模型若仍设为 3000，请在模型配置改为至少 8000（可选 16000，开启思考时按供应商能力预留更多）。拆解任务默认跟随模型上限，最低 8000，低于阈值不会调用供应商。官方 DeepSeek 混合模型 Chat 接口的默认拆解关闭思考，可在高级设置切换；其他平台不自动发送该专用参数。供应商返回的部分正文先保存再标记失败，推理阶段只记录状态和 Token 数。预算不会自动提高，截断报告不可确认。

## 0.4.2 输入输出自由配置

单次、每日、每月费用预算继续生效。模型配置是默认输出额度，单次任务可覆盖，0 或留空使用默认值；软件不设 8000 Token 最低门槛、固定数值上限或文本字数上限，不静默裁剪原文、补充要求或项目上下文。供应商仍决定其模型支持的输出额度及上下文容量。已返回文本即使未形成完整报告也可导出。历史版本段落中的输入输出上限已被本版替代。

## GitHub Skill 安装

Skill 中心点击「从 GitHub 地址安装」，粘贴公开 Skill 目录或 SKILL.md 地址，读取预览后选择用途、平台和账号范围保存。与上传同一目录的 ZIP 使用同一解析及版本流程；参考文档和原始规则均保留，脚本源码只读保存，不自动运行或启用外部数据/支付服务。GitHub 来源固定到提交，安装使用预览时的包。私有仓库暂不支持；GitHub 网络与访问频率限制会明确提示。

## 检查后再去 AI 味

先生成并检查正文，在左侧「检查后使用的去 AI 味 Skill」下拉框选择规则，点击「执行去 AI 味」。打开的面板可核对本次处理全文和更换规则；运行只执行所选 Skill，结果与处理前全文比较后采纳。选择规则不会自动调用模型，AI 创作初稿不会受旧自动后处理开关影响。后续导入用途为「去 AI 味后处理」且适用当前稿件平台的 Skill，会进入该下拉列表。
